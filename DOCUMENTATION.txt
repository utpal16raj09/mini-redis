                       MINIREDIS ARCHITECTURE & TECHNICAL GUIDE
===============================================================================

1. EXECUTIVE OVERVIEW
-------------------------------------------------------------------------------
MiniRedis is a high-performance, single-threaded, event-driven in-memory Redis 
server clone written in modern C++17 from scratch.

It closely replicates the core architectural design of official Redis:
  - Single-Threaded Event Reactor Loop using Linux epoll
  - Native RESP2 (Redis Serialization Protocol) Parser & Encoder
  - In-Memory Polymorphic Storage Engine (std::variant)
  - Dual-Mode TTL Eviction (Lazy Eviction + Active 100ms Sampling)
  - Append-Only File (AOF) Persistence Logging & Crash Recovery Replay

FILE 1: include/network/Socket.hpp & src/network/Socket.cpp
  - Wraps Linux POSIX socket APIs (socket, bind, listen, accept, fcntl).
  - listenOn(port): Configures SO_REUSEADDR, binds to 0.0.0.0:port, listens.
  - setNonBlocking(bool): Uses fcntl(fd, F_SETFL, flags | O_NONBLOCK).
  - acceptConnection(): Accepts new client connection and extracts client IP/port.

FILE 2: include/network/Connection.hpp & src/network/Connection.cpp
  - Manages per-client socket state, read_buffer_, and write_buffer_.
  - onRead(): Reads non-blocking recv() data, parses RESP frames via RespParser,
    dispatches requests to Router, and appends serialized responses to write_buffer_.
  - onWrite(): Non-blocking send(MSG_DONTWAIT) flushes pending bytes in write_buffer_.

FILE 3: include/network/EventLoop.hpp & src/network/EventLoop.cpp
  - Core single-threaded epoll reactor loop.
  - epoll_create1(0): Creates Linux kernel epoll instance.
  - addFd() / updateFdFlags(): Manages EPOLLIN / EPOLLOUT socket interest flags.
  - run(): Main epoll_wait cycle handling new connection accepts, client reads,
    non-blocking writes, and executing active expiration purging every 100ms.

FILE 4: include/protocol/RespParser.hpp & src/protocol/RespParser.cpp
  - Stateful stream parser for RESP2 protocol (+, -, :, $, *).
  - RespValue: Struct holding parsed variant (SimpleString, Error, Integer, BulkString, Array, Null).
  - parse(input_buffer): Scans for CRLF (\r\n) terminators, extracts payload,
    and consumes only completed frames from input_buffer.

FILE 5: include/storage/Value.hpp
  - Defines polymorphic Value struct:
    enum ValueType { String, Hash, List, Set }
    variant<string, unordered_map<string, string>, deque<string>, unordered_set<string>>
    optional<steady_clock::time_point> expire_at
  - Helper functions: isExpired(), getTtlSeconds().

FILE 6: include/storage/Database.hpp & src/storage/Database.cpp
  - In-memory key-value database map (unordered_map<string, Value>).
  - Implements String, Hash, List, Set operations and TTL expiration.
  - purgeExpiredKeys(sample_limit): Performs active background TTL eviction.

FILE 7: include/storage/AofEngine.hpp & src/storage/AofEngine.cpp
  - Append-Only File (AOF) persistence logger & startup recovery replay.
  - append(command): Writes RESP-serialized mutating write commands to appendonly.aof.
  - loadAndReplay(router): Replays appendonly.aof line-by-line on boot to restore database state.

FILE 8: include/commands/Router.hpp & src/commands/Router.cpp
  - Command pattern dispatcher. Parses RESP request arrays, routes commands
    to Database methods, and forwards write operations to AofEngine.

FILE 9: src/main.cpp
  - Bootstraps Database, AofEngine, Router, replays persistent AOF data,
    and starts EventLoop on port 6379.

4. CORE SUBSYSTEM IMPLEMENTATION DETAILS
===============================================================================

[A] Non-Blocking epoll Reactor Pattern
  1. Socket handles are set to non-blocking (O_NONBLOCK).
  2. Main loop calls epoll_wait(epoll_fd, events, MAX_EVENTS, 100).
  3. Server socket EPOLLIN accepts new connections without blocking.
  4. Client socket EPOLLIN reads data; EPOLLOUT flushes pending write buffer.
  5. All state mutations run on single thread -> Zero mutex lock overhead.

[B] Dual TTL Expiration Strategy
  1. Lazy Eviction (On-Access): Checked during GET, EXISTS, HGET, etc.
     If key is expired, it is erased immediately and nullopt is returned.
  2. Active Eviction (Background Sampling): Every 100ms epoll_wait timeout,
     purgeExpiredKeys(20) samples random keys and erases expired entries.

[C] AOF Persistence & Crash Recovery
  1. Mutating commands (SET, DEL, INCR, HSET, LPUSH, SADD, etc.) are written
     to appendonly.aof in RESP wire format.
  2. On startup, AofEngine parses appendonly.aof and replays commands into
     Router to restore the exact memory state.

5. SUPPORTED COMMANDS REFERENCE
===============================================================================

  COMMAND       ARGUMENTS & EXAMPLE              RESP RESPONSE
  -----------   ------------------------------   ------------------
  PING          PING "hello"                     "$5\r\nhello\r\n"
  INFO          INFO                             "$...info...\r\n"
  FLUSHDB       FLUSHDB                          "+OK\r\n"
  SET           SET key val [EX sec | PX ms]     "+OK\r\n"
  GET           GET key                          "$3\r\nval\r\n"
  INCR          INCR counter                     ":1\r\n"
  DECR          DECR counter                     ":0\r\n"
  DEL           DEL key1 key2                    ":2\r\n"
  EXISTS        EXISTS key                       ":1\r\n"
  EXPIRE        EXPIRE key 60                    ":1\r\n"
  TTL           TTL key                          ":58\r\n"
  KEYS          KEYS *                           "*1\r\n$3\r\nkey\r\n"
  HSET          HSET hash field val              ":1\r\n"
  HGET          HGET hash field                  "$3\r\nval\r\n"
  HGETALL       HGETALL hash                     "*2\r\n$5\r\nfield\r\n$3\r\nval\r\n"
  LPUSH / RPUSH LPUSH list val1 val2             ":2\r\n"
  LPOP / RPOP   LPOP list                        "$4\r\nval2\r\n"
  LRANGE        LRANGE list 0 -1                 "*1\r\n$4\r\nval1\r\n"
  SADD          SADD set mem1 mem2               ":2\r\n"
  SMEMBERS      SMEMBERS set                     "*2\r\n$4\r\nmem1\r\n$4\r\nmem2\r\n"

6. BUILD AND RUN INSTRUCTIONS
===============================================================================

  1. Build:
     mkdir -p build && cd build
     cmake ..
     make

  2. Run Server:
     ./miniredis

  3. Test with official redis-cli:
     redis-cli -p 6379 PING
     redis-cli -p 6379 SET mykey "Hello MiniRedis"
     redis-cli -p 6379 GET mykey
